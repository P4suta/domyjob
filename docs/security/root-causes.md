# Root causes and required mechanisms

Every review finding is traced to a class of mistake.
The table states the mechanism and check required to close each class; naming them here does not establish that they are implemented.
A class is closed only when its production API or repository task prevents the unsafe flow, a build gate rejects bypasses, and a test exercises the property at its boundary.
The implementation status of the seven overarching laws is recorded in [laws.md](laws.md).

| Class | What made it writable | Required mechanism | Required check |
| --- | --- | --- | --- |
| RC-A. Trust decided by plain values | `bool` for "paired", `Option` for "has checksum", `Option<psk>` choosing a Noise pattern, pinning as a separate step | Proof types with private constructors: `Verified<T>`, `Authorized<R>`, `Channel` returned only after the peer matched an `Expect` | Rust privacy; handlers accept only the proof type |
| RC-B. Unbounded resources | `read_line`, `read_to_end`, `fs::read`, `read_to_string`, child `.output()`, `thread::spawn` per accept, and whole-job maintenance lists | Bounded readers, file loads, and child output with explicit byte budgets, streaming for large blobs, a connection `Permit` counted overall and per source address, a job-admission proof, and bounded maintenance traversal | The syntax gate rejects unbounded stream, text, binary file, and child output reads outside `bounded.rs` and direct job publication outside `Store`; the type of production staging requires `JobAdmission`; tests exercise the size and admission boundaries, concurrent child pipes, streamed content verification, and maintenance batches |
| RC-C. Ambiguous stream end | Raw EOF and an authenticated close meant the same thing | `Frame::{Data, Close}` inside the ciphertext and a reader state machine `Open, Closed` | Exhaustive match on the frame enum |
| RC-D. Secrets in ordinary types | `Vec<u8>` secret with derived `Debug` and `Clone` | `Secret<T>`: no `Clone`, redacted `Debug`, zeroized on drop | The gate refuses `Debug`/`Clone` derives on types holding `Secret` |
| RC-E. State files written ad hoc | `fs::write` with default permissions, read-modify-write races | One `StateFile<T>`: owner-only directory and file, permission check on read, atomic replace, a lock around updates | Clippy disallows `fs::write` and `File::create`; the syntax gate rejects ordinary `fs::read`, raw JSON state operations in production, construction outside typed owner methods, and direct byte reads and writes in the client-origin function |
| RC-F. Untrusted content reaching sinks | Remote names, logs, and repository files flowed as `String`/`Vec<u8>` into terminals, config, and target selection | `Labeled<T, Origin>` for everything a peer or repository supplies; leaving it needs a named neutralizer (`for_terminal`, `as_machine_name`) | Wire and repository types deserialize into origin-labeled values |
| RC-G. Mutable external references | `latest`, action tags, `curl \| sh`, a checksum from the same origin | A signed release manifest verified against keys compiled into the binary, version monotonicity, workflows pinned by digest | `Verified<Binary>` required by install and update; gates over `.github/` |
| RC-H. All-or-nothing authority with no lifecycle | Pairing implied full remote execution, nothing could be listed, revoked, or audited | `Grant` with a set of `Capability`, an exhaustive `decide`, revocation, and a hash-chained audit log | `decide` has no wildcard arm; `wildcard_enum_match_arm` is denied crate-wide |
| RC-I. Dangerous defaults | `0.0.0.0` default bind, discovery always on, running as root | `Exposure::{Loopback, Tailnet, Lan, Explicit}` with the risky variants requiring an explicit argument; refusal to run elevated | The listener accepts only `Exposure`, never a raw address |
| RC-J. No human in the loop where only a human can decide | Pairing enrolled a key without confirmation | A short authentication string shown on both sides and confirmed before any grant is written | The grant constructor takes a `Confirmed` token |
| RC-K. Repository content choosing policy | A pushed `domyjob.toml` picked targets, commands, and environment | Policy comes only from local configuration; repository files may request, never grant | `LocalPolicy` and `RepositoryRequest` are distinct types; `ApprovedProjectJob` is required to construct a project order |
| RC-L. Untrusted values in argument positions | `curl -d {message}` let a server-chosen `@path` read a local file | Template bindings are typed by trust; untrusted values have no path into an argv and reach external programs only on stdin | `Bindings` for argv accept only `Trusted` values |
| RC-M. Hand-made concurrency | Lock files taken with `create_new` and stolen by inferring liveness from heartbeats | Operating-system file locks only, released by the kernel when the holder dies; a supervisor holds its job's lock for its whole life, so "alive" is a fact the kernel keeps | Clippy rejects `OpenOptions::create_new` by default, and the syntax gate permits it only in four named functions that create ordinary files; `lock.rs` has no exception |
| RC-N. Escaping written per language by hand | PowerShell's typographic quotes and cmd's `%VAR%` were missed | Each quoting rule is an exhaustive classification of every character, with property tests over arbitrary strings | Tests round-trip every rule through the real interpreter where available |
| RC-O. Identifiers chosen by the less trusted side | Job ids came from the client; warm workspaces were shared across trust levels | The node assigns job ids and records the submitting principal; workspaces are keyed by project and trust level | `JobId::generate` is callable only from the node |
| RC-Q. Partial results passing as whole ones | A stream cut by the network ended in EOF and was taken as the end of the file or the log; an error after the reply had started was written into the user's file | Every stream is framed: chunks, then an ending that carries the byte count and a BLAKE3 digest or the sender's refusal; no ending means "cut" | `framed::unframe` is the only reader of streamed replies, and its property test cuts every payload at every offset |
| RC-R. Crashes leaving state that blocks the next run | An audit entry written without its head, a workspace half filled, a job whose supervisor died, a staging directory never published, a slot that cannot be cleared | Each record is written so the next reader can finish or undo it: repair under the audit lock, intent recorded before filling, a sweep on every request that acts only on what a free lock proves abandoned, and a trash area for what cannot be removed in place | Tests that cut each write at its crash points and run the next request |
| RC-S. A full disk that stops everything | A job's log filled the disk; after that every command failed on a small record it wanted to rewrite, including the ones that only read, and nothing gave space back | Reads never depend on a write: an audit head that cannot be saved is used from memory, and the client rewrites its records only when they change and warns when it cannot; the sweep gives back space in the order that loses least, idle workspaces, then the largest finished logs, then sources that only finished jobs used, and never a job record; a full disk is reported as such | Tests make the audit head unwritable, drive the sweep with the disk reported short, and classify a full disk however deeply it is wrapped; a live test fills a small tmpfs and checks that reading, recovery, and history all survive |
| RC-P. Time used as evidence | A heartbeat older than 15 seconds meant "dead", sleeps polled for kill requests and free slots, a grace period separated SIGTERM from SIGKILL, mtimes meant "unchanged", pairing codes, grants, and release manifests expired, handshakes had deadlines | Every such question is answered by the event itself: a held lock for liveness, a blocking lock for a free slot, a local socket for kill, wait, and log delivery, a pipe or kernel event for "the supervisor started", content hashes for "unchanged", counts for pairing attempts and connections, explicit revocation for grants, a version high-water mark for releases | `clippy.toml` disallows every clock, sleep, timeout, and file timestamp API; the gate refuses time types and timeout methods everywhere, tests included; the wall clock is read only by `clock::Timestamp::observe`, whose type has no ordering; the single exception, a silent peer, lives in `liveness.rs` and decides only whether to give up a connection |
| RC-T. Host-only type checks and reusable build artifacts | A new private argument type compiled on macOS but had no import in a Windows-only module; Windows PowerShell 5.1 returned `null` for `Start-Process.ExitCode` after a manual wait, and the falsey value let a failed build stage the previous executable from a shared Cargo target directory | The CI matrix compiles every target on each supported operating system; a source build runs Cargo directly in a PowerShell job and checks its native exit code and job state, holds an operating-system lock through compilation and transfer-specific staging, requires an executable, and verifies its embedded source stamp before promotion | Windows Clippy covers the platform module; Windows tests build valid and invalid source with an old executable present, require failure to stage nothing, and require success to stage a new executable |
| RC-U. Operation identity confused with session identity | A process-wide session name was used for Windows upload files, so two builds in one process overwrote and deleted each other's base64 input; the Cargo target and incoming executable were also shared | A private `TransferId` wraps a fresh random `Nonce`, and setup fails if entropy fails; typed remote commands carry that ID through upload, transfer-specific staging, verification, promotion, and best-effort cleanup on error; an operating-system lock protects the shared target and stable source path through staging | Rust signatures require an ID for every setup command; the syntax gate rejects a fixed incoming filename; Windows tests build two different sources concurrently in one cache, run both staged executables, and promote each one by its own ID |
| RC-V. Test failures shared process-global injection state | `fail::cfg` and a single crash slot let parallel tests clear or replace each other's fault plan; an empty path tag injected `pull::swap` faults into unrelated tests | Test guards register rules independently by ID and remove only their own rules on drop; `inject_after` requires an absolute `Path` scope and counts only matching operations; crash guards are also scoped by path | Clippy bans direct `fail::cfg` and the syntax gate confines process-global scenario setup to `faults.rs`; concurrent tests arm the same site under separate paths and prove unrelated paths remain unaffected; the full test suite runs in parallel on each supported operating system |
| RC-W. One identifier served unrelated resource limits | Making the process session ID long enough for transfer filenames lengthened OpenSSH `ControlPath`; even after shortening the ID, `%C` plus OpenSSH's temporary socket suffix exceeded macOS's Unix socket limit, so a later shared connection exited before sending a reply | `SshSessionId` is separate from `TransferId`, uses a short random value, and fails closed if entropy fails; `SshControlId` combines it with a fixed-length digest of the machine identity so simultaneous hosts use separate socket names; the path gate reserves 32 bytes for OpenSSH's temporary name and rejects unknown expansion tokens | A unit test renders the built-in transport with a representative Mac cache path and checks identity separation, temporary-name room, and unbounded tokens; end-to-end source setup and subsequent doctor must pass with the default transport |
| RC-X. Recursive wildcard matching on unbounded strings | A local trigger's `refs` patterns and a hook's `--ref` entered as plain `String`; every `*` branched over every remaining character, so a crafted pattern and ref could consume exponential CPU | `RefPattern` and `EventRef` reject values beyond 1024 bytes and control characters at deserialization and CLI parsing; matching scans ordered literal segments without recursion | The syntax gate requires the typed fields, boundary tests enforce the byte budget, and a property test compares matching against an independent dynamic programming oracle |
| RC-Y. A snapshot retained an ambient source path | `Origin::Disk(PathBuf)` reopened an absolute path after the source was inspected, so replacing a parent directory with a link could redirect later reads outside the selected root | A private `DiskOrigin` retains the directory handle opened before inspection and a validated `RelPath`; archive and upload read only through that handle, stream within explicit budgets, and check the captured digest | Rust privacy prevents constructing a disk origin from a plain path; a test swaps an intermediate directory for an external link and requires archive creation to fail |
| RC-Z. Test admission depended on host CPU count | Nextest's default ran one test process per available CPU, making full-suite load vary across machines; the Mac suite intermittently reported leaked handles in different audit tests at high parallelism | The repository Nextest profile fixes four concurrent test processes while keeping leaked handles fatal | The unqualified full Nextest command must pass, and a test that truly retains a child output pipe must still fail |
| RC-AA. An older runtime could delete a newly installed copy | Cached managed binaries lived in version directories, and a running older node deleted all but its own and two lexicographically highest directories; hash order does not express install order | Keep each managed build as a versioned regular file in the cache root so the legacy directory sweeper cannot remove a new installation, while transfer stages retain separate IDs | The command tests require the file layout for each operating system, a boundary test runs legacy cleanup with a new managed file present, and source setup plus native tests run on the supported machines |
| RC-AB. Private directory creation depended on a child process | Windows created a directory first and then launched `icacls` to remove inherited access; an observed `0xc0000142` failure stopped a job before its command started | Convert a validated user SID into an owner-and-SYSTEM-only security descriptor and pass it to `CreateDirectoryW` for each missing ancestor | The syntax gate rejects a production `icacls` invocation in `platform.rs`; a Windows test reads the resulting ACL and the native full suite runs under the standard parallel profile |
| RC-AC. Existing state was trusted without inspecting Windows ACLs | `platform::ownership` returned `Private` for every Windows metadata record, including files and directories with an Everyone ACE | Require an open file or directory handle for ownership classification; inspect its owner and every DACL ACE, accept only the current user and SYSTEM as access grantees, and reject reparse points | The function signature requires a handle and returns an I/O result; Windows boundary fixtures create a file and directory with an Everyone ACE and require rejection; the native Windows suite checks the real API path |
| RC-AD. Upload and submission did not share a CAS lifetime | `Missing`, `Upload`, and `Submit` were separate exchanges, so a concurrent collector could delete uploaded blobs before `Submit` began; submission-time retirement and low-disk collection could also treat the incoming source as unreferenced | Replace the split requests with one two-round `Submit` exchange: receive the manifest, request missing content, receive exactly those blobs, and admit the job while a private `SnapshotTransfer` owns the collection lock; staged and published specs then provide the durable CAS roots | The request enum and syntax gate prohibit the old split operations, and a wire test requires their rejection; a concurrent collection test checks the lock after the first reply, and a real local submission checks both rounds through the supervisor; native suites must pass on all supported operating systems |
| RC-AE. Tests and ordinary builds shared a mutable executable | A Nextest integration test launched `CARGO_BIN_EXE_domyjob` with fault injection enabled, while a concurrent plain `cargo run` rebuilt the same `target/debug/domyjob` without that feature; the test then observed a successful reply instead of its expected abort | Give all test tasks a dedicated Cargo target directory, including the fleet test job, so ordinary builds cannot replace an executable after the test suite has selected it | The project test task must run with `CARGO_TARGET_DIR=target/test`; concurrent ordinary builds use the default target, and the crash-process test must pass while both execute |
| RC-AF. Each source change multiplied the remote build cache | Cargo used a separate target for every client build stamp and source archive, leaving 20.3 GB of near-duplicate Windows targets and zero free disk space | Serialize source replacement, Cargo, and transfer-specific staging with an operating-system lock; compile from one stable source path into one reusable target, then remove the source before releasing the lock; Unix hosts without a locking command retain the isolated-target fallback | `storage-scout` measured the old targets and validated four removals that recovered about 2.7 GB; concurrent Windows source-build tests keep distinct staged binaries, and live Linux and Windows wire-mismatch upgrades exercise the new path |
| RC-AG. Cleanup determined the outcome of a successful Windows build | Moving the extracted source to its stable compilation path left its original name absent; PowerShell 5.1 set `$?` to false when the final `Remove-Item` saw that name, even with `-ErrorAction SilentlyContinue`, so an otherwise successful encoded script exited 1 | Check each cleanup path before removal and exit 0 only after the build, staging, and `finally` block have completed; terminating failures still bypass that exit | A native PowerShell fixture confirms the false status from removing an absent path; Windows source-build tests require successful staging and removal of both temporary source paths, and a live wire-mismatch upgrade must complete |
| RC-AH. A growing build script exceeded the Windows command-line limit | Embedding the entire source-build PowerShell script in `-EncodedCommand` expanded it beyond the `cmd` limit, so the build could not start | Send the script and source archive as separate base64 sections on stdin, and use a short, fixed-shape PowerShell bootstrap to decode and run them | A unit test bounds the complete Windows build command below 8,000 characters; Windows tests execute the framed transfer, and a live wire-mismatch upgrade must complete |
| RC-AI. Syntax checks could be hidden behind imports or suffix-matched owner names | `use serde_json::from_slice as decode` made a forbidden decoder call look like an ordinary local function, while `fake_ingress.rs` inherited an owner's exception | Reject direct imports of protected functions, aliases of protected namespaces and decoder types, protected type aliases, production glob imports, and suffix-only owner matches; let compiler-resolved Clippy reject raw JSON and TOML decoder calls | The syntax gate tests direct, renamed, grouped, glob, and type-alias forms and exact owner names; Clippy checks resolved decoder calls across all targets |
| RC-AJ. A separate Cargo graph escaped dependency checks | The fuzz workspace had its own Cargo.lock, but the deny and audit tasks examined only the root graph; its package lacked a license declaration, and libFuzzer's NCSA license was absent from policy | Discover every non-generated Cargo.lock and run license, source, and advisory checks for each adjacent manifest and lockfile | The dependency task fails on a missing manifest or failed check, and its fixture proves that a newly added nested graph is discovered without editing the task list |
| RC-AK. Job spawning depended on caller ordering | `Group::spawn` accepted a raw `Command`, while the supervisor had to remember to clear inherited environment variables and set job identity before calling it | `Launch::prepare` clears the command environment and adds explicit job variables; a private `PreparedJobCommand` is required by `Group::spawn` | The syntax gate rejects a raw spawn signature, public proof fields, forged proof literals, and extraction outside `proc.rs`; a boundary test checks the exact environment and redacted debug output |
| RC-AL. Revocation selected two different peers with one string | A machine name can have the same syntax as another key's fingerprint, so matching both in one `retain` predicate could revoke unrelated records; an unknown selector was rejected only after rewriting the trust file | Parse the revocation request into name, fingerprint, or inferred selector variants; reject ambiguous and unknown selectors under the trust-file lock before any write, with explicit prefixes to disambiguate | The syntax gate requires the private parsed selector at `Trust::remove` and rejects construction outside parsing; a boundary test creates the collision, requires rejection without attempting a state write, and checks that each explicit selector revokes only its intended grant |
| RC-AM. Generic ingress grants decoding to unowned shapes | Blanket `Ingress` implementations for maps and vectors, plus primitive implementations, let a caller choose an arbitrary raw container or scalar at an external-input boundary without naming its schema | Remove those implementations and require a concrete domain type for every decoder; persisted environment and workspace differences use private transparent state types, preserving their JSON format | The compiler rejects decoding raw collections or primitives; the syntax gate requires a concrete type defined in the same module, including macro-generated domain newtypes, and rejects aliases; state-file and job-stage tests exercise the named types |
| RC-AN. Slot discovery trusted arbitrary directory names | The queued-job status path collected and sorted every name under the slot directory, then parsed noncanonical aliases and unbounded indices as slots; the supervisor separately scanned the fixed slot range | Generate canonical slot lock paths from `Concurrency::MOST` in one `Store::held_slots` method and use it for both queue admission and status | The syntax gate rejects directory scans in store slot discovery and direct supervisor probing; boundary tests require slot 63 to count, aliases and slot 64 to be ignored, and only a canonical held slot's malformed holder to cause an error |
| RC-AO. Directory ordering duplicated unbounded collection | Pull journals and legacy binary directories were collected into unbounded vectors before sorting, while CAS and log scans implemented the same bounded rescan loop separately | `bounded::SortedScan::walk` owns the ordering cursor, fixed batch capacity, and typed continue-or-stop decision; pull history streams its summary and retains only the newest 31 entries before deleting sorted batches, and legacy cleanup retains only two other directory names | The syntax gate restricts direct directory reads to reviewed streaming owner functions, and callers cannot access the private batch step; generic tests cross multiple batches with duplicate unsorted keys and stop before a second scan; CAS, idle workspace projects, log, pull, and legacy cleanup boundary tests cross the 256-entry boundary and check complete, ordered results and preserved locked or current entries |
| RC-AP. CLI fanout duplicated unbounded thread loops | Each short multi-machine CLI operation spawned one thread per item and rebuilt its own channel and result loop, while `wait` and `retry` accepted an arbitrary number of job references; long-running `watch` also spawned one thread per unbounded input | Short operations use the shared sixteen-worker `fanout` scheduler with a sixteen-result channel, which owns arrival delivery, panic conversion, and cancellation after a fallible consumer fails; a private-field `ConcurrentBatch<T, 64>` proof bounds the long-running watch set before its spawning function can run | The syntax gate rejects new CLI thread scopes and spawns outside the reviewed long-running functions and requires the watch spawning signature to take `ConcurrentBatch`; tests cover the worker count, consumer failure, and both sides of the concurrent-batch limit |
| RC-AQ. Queue waits observed irrelevant locks | Every queued supervisor watched every occupied slot even while an earlier queued job prevented its admission; a changed predecessor was ignored until the old predecessor exited | An exhaustive `Admission` match registers only the event that can change the current decision: `EarlierWaiter` carries its predecessor path, `Full` watches occupied slots, and `Paused` registers no lock watcher; a new predecessor replaces the tracked path | A boundary test covers every admission variant and verifies the exact registered paths, while another changes the predecessor before the old lock releases and requires the new path to be registered |
| RC-AR. A warm workspace scan used an unlimited lock range | `OsLock::first_free` accepted a caller-chosen `usize`, and warm workspace allocation passed `usize::MAX`; its unreachable exhaustion case then reused slot zero without holding its lock | `OsLock::first_free` generates exactly the canonical 64 indices from `Concurrency::MOST` for both job and workspace slots, and warm allocation returns a named error if all are held | The compiler no longer accepts an arbitrary scan length, and a boundary test holds every slot, requires failure without creating slot 64, then releases slot zero and requires its locked reuse |
| RC-AS. Workspace cleanup accepted aliases for lock slots | Creation used only slots 0–63, but cleanup parsed every numeric directory name, so `01` borrowed the lock for `1` and `64` produced a lock outside the valid range | A private-field `SlotIndex` enumerates only canonical slots, constructs every slot-lock path, and gives cleanup a fixed range to probe instead of parsing directory names | The compiler prevents arbitrary slot construction, the syntax gate rejects a public field or a return to numeric directory parsing, and boundary tests keep aliases and out-of-range directories untouched while checking all canonical slots and the complete bounded clean report |
| RC-AT. Disk cleanup depended on directory enumeration order | Idle workspace cleanup visited scope and project entries in filesystem order, then stopped when enough disk space had been recovered, so identical state could evict a different project | `SortedScan` visits project roots in fixed batches and lexical order, then `SlotIndex` visits each project's canonical slots in numeric order; non-directory entries are skipped | The syntax gate requires the sorted project traversal, and a boundary test creates more than 256 projects in reverse order and requires a complete ascending visit |
| RC-AU. An invalid remote version looked old | `is_newer` returned `false` when version parsing failed, so a peer with an unparsable version could enter the automatic replacement path | `VersionRelation` distinguishes newer, older or equal, and unparsable; the last result rejects installation with a distinct error that carries the reported version | The syntax gate requires the typed comparison in the discovery path and rejects the old boolean helper; boundary tests require invalid input to fail before the installation branch |
| RC-AV. New errors inherited an implicit retry decision | `matches!` marked a short list of transport errors as transient and treated every new `RemoteError` variant as final without review | A `Retryability` enum and exhaustive match classify every remote error; stream interruption is retryable while damaged and local-output streams are final | The crate-wide enum-match lint makes an added remote error fail compilation until classified, the decision-signature gate forbids a boolean regression in `client.rs` and `remote.rs`, and a boundary test exercises both retryable and final stream outcomes |
| RC-AW. A new job phase inherited refusal without review | `matches!` listed allowed lifecycle moves and silently classified every other pair as invalid, including pairs involving a new `Phase` variant | An exhaustive `PhaseTransition` match names both advancing and refused moves for every source and destination; `set_phase` consumes that typed decision | Adding a phase fails compilation until its complete transition policy is written; the syntax gate rejects a boolean or `matches!` regression, and the lifecycle boundary test checks a skipped move and a rewind after completion |
| RC-AX. Workflow lint depended on Git metadata | `actionlint` without file arguments searched upward for a Git checkout, so the full check failed in a domyjob source snapshot even though the workflow files were present | `cargo xtask workflows` discovers every YAML file in `.github/workflows` and passes the exact file paths to `actionlint` | A fixture discovers both YAML extensions without a `.git` directory, the task fails when none exist, and the same `mise run check` runs in a checkout and a transferred Linux workspace |
| RC-AY. | RC-AZ. Test debug symbols exhausted Windows build space | A separate test target accumulated 4.8 GiB of artifacts, leaving about 730 MiB free; MSVC then failed to write a program database with `LNK1318` | Set the shared Cargo test profile to `debug = 0` while retaining the dedicated test target that protects feature-specific test executables | Native Windows `mise run check` passes 423 tests and both dependency graphs; the new test target occupies about 1.8 GiB and leaves about 2.3 GiB free |
| RC-BA. Automatic source builds used the slow distribution profile | Every source change produced a new build stamp and rebuilt the remote executable with release LTO and one codegen unit, so a Linux refresh took about 117 seconds | Use the dedicated `remote` Cargo profile for source builds on Unix and Windows; inherit the incremental development profile, omit debug symbols, and retain modest optimization while release artifacts keep their distribution profile | A Linux automatic refresh takes about 55 seconds from a cold profile and 6 seconds after a source change; an isolated native Windows build takes about 88 seconds cold and 19 seconds incrementally, and the source-build script tests require the matching profile and executable paths |
| RC-BB. The binary stamp included unrelated repository tools | The stamp scanned every Rust, TOML, and lockfile in the repository, and later still hashed all of `mise.toml`, so adding a verification task forced a remote executable refresh even though its binary inputs were unchanged | Hash only the product crate's source and build script plus its workspace manifest, lockfile, toolchain, and the parsed `tools.rust` value from `mise.toml`; still archive the full checkout for the remote build and compare the stamp before and after archiving | Boundary tests keep the stamp fixed after `_typos.toml`, `xtask`, and `mise.toml` task edits, change it after a product source, manifest, or Rust tool edit, reject a link inside product source, and retain the entry, file, path, depth, and TOML parsing budgets |
| RC-BC. The Windows build fixture drifted from the selected Cargo profile | Native source-build tests used a tiny Cargo manifest with no `remote` profile and placed their stale executable under `release`, so changing the production build profile made three tests fail before exercising their intended success and failure paths | Make the fixture declare the selected profile and place its stale executable at the exact output path the build script reads | The Windows CI test job runs the invalid, valid, and concurrent source-build fixtures natively and fails if the profile or output path diverges |
| RC-BD. | RC-BG. Advisory checks were mistaken for source review | `cargo deny` and `cargo audit` checked licenses, sources, and known advisories but did not require anyone to review a dependency's code before a new version entered the graph | CI now runs `cargo vet` over every discovered Cargo lockfile with nine imported audit sets pinned in `imports.lock`; exact-version exemptions are explicit and a new unvetted version fails until reviewed or deliberately exempted | Mac and native Linux vet runs pass on the root and fuzz graphs; deleting the `ring` exemption in an isolated copy makes `ring:0.17.14` fail the gate; 267 existing exemptions remain, so the review property is still open |
| RC-BH. An unremovable workspace blocked all later disk reclamation | A job left root-owned output inside its warm workspace; low-disk cleanup moved the workspace to trash, then its failed removal stopped cleanup of other workspaces and logs and refused unrelated submissions | Use a distinct quarantined-workspace result after an atomic move; automatic reclamation continues to other candidates, explicit clean returns the removal error, and trash sweeping tries every entry before reporting failure | Fault injection proves continued log reclamation, explicit clean failure, and removal of later trash entries; the updated Linux receiver submitted and completed a job while the root-owned tree remained in trash, and full Mac, Linux, and Windows suites passed |
| RC-BI. ## Crate-wide lint escalations

The classes above share one habit: a default branch or a default value silently decided a security question.
So the crate also denies `clippy::wildcard_enum_match_arm`, `clippy::match_wildcard_for_single_variants`, and `clippy::fallible_impl_from`, and the gate refuses `#[derive(Default)]` on any type in a security module.

## Known open classes

RC-BG remains open because the 267 exact-version cargo-vet exemptions include cryptography, input-parsing, and process-control dependencies whose source review has not been established.
RC-BD remains open for enum patterns hidden inside expression and procedural macro expansion; the syntax gate now reviews item macros and checks variable-length patterns with a rest marker on either or both sides.
RC-BE is closed for the installed Windows receiver: the explicit ACL migration secured all 4,578 eligible entries, a second full inventory found none, and the 968-entry audit log verified.
The Mac client's `doctor win` rebuilt the Windows executable from the sent source and passed, then a `hostname` job succeeded through the same client path; a further scan found no legacy ACLs among 91,250 state entries.
RC-B remains open because other allocating reads and thread-spawn paths still need an end-to-end resource audit; network connections have overall and per-source permits, local control connections have a 32-session permit, MCP input lines have a 1 MiB budget and MCP workers have a 32-permit cap with active-only cancellation state, configuration and selector targets are capped at 64 machines, selector expansion has a shared 256-term work budget, general fanout uses at most 16 workers, log scanning stores a 64 KiB prefix per line and returns at most 1024 lines, source snapshots have 100,000-entry and 16 MiB path budgets, materialized revision content is capped at 64 MiB, directory hashing uses four workers, source archives are capped at 64 MiB, child output has per-purpose budgets, and blobs are streamed when they may be larger.
Queue admission now streams job IDs, retains only the earliest live predecessor, and permits at most 64 tracked slot lock watchers plus one current predecessor path per queued supervisor; job listing keeps at most 1000 recent jobs and refuses excess unreadable records.
Its typed admission decision now registers only the predecessor while one is ahead, only slot locks while capacity is full, and no lock watchers while paused; replacing a predecessor updates the tracked watch immediately.
Queue admission and queued-job status now enumerate the same 64 canonical lock paths through `Store::held_slots`, without collecting arbitrary directory names or accepting alternate spellings of an index.
CAS, workspace, finished-log, pull-journal, and legacy-binary cleanup now share `bounded::SortedScan`, which retains at most 256 sorted keys per pass and advances after each completed batch.
Its constructor fixes the 256-key capacity, so a caller cannot choose a larger scan allocation.
Pull history keeps only the 31 newest existing entries needed when opening a new journal, while the legacy binary sweep keeps only two other directory names before its deletion pass.
A machine admits at most 64 unfinished published or staged jobs, and the production staging API requires a `JobAdmission` tied to the collection lock.
Publication takes that lock too, so a collection pass cannot miss a job moving from staging to the published directory; retirement retains at most its requested count of newest finished jobs, and finished logs and stored CAS blobs are scanned in batches of 256.
Idle workspace maintenance now visits projects in bounded sorted batches, probes only the 64 canonical paths per project, and never associates an alias with another workspace's lock.
Clean replies retain only the eight largest details and an aggregate for every omitted item; `CleanReportItems` makes the nine-item maximum a construction, decoding, and wire-schema rule, and a test covers more than 256 canonical workspaces across projects while checking the complete byte total.
Workspace size measurement now streams directory entries with at most 64 open iterators and explicitly refuses a deeper tree; its boundary test covers a directory wider than one maintenance batch and both sides of the depth limit.
Job and warm workspace lock scans now share the fixed 64-slot `OsLock::first_free` API; a full warm range fails instead of reusing an occupied workspace without a lock.
RC-B remains open because managed binary files need a retention scheme based on active installations, and other allocating reads and thread-spawn paths still need an end-to-end resource audit.
An old predecessor's blocked watcher can remain after a new predecessor is tracked, so aggregate watcher lifetimes still need a cancellation or operating-system event mechanism.
Short CLI operations now use the shared sixteen-worker scheduler, and long-running watch accepts at most 64 jobs through a bounded input proof; the remaining thread paths still need the end-to-end audit.
CAS collection now caps its mark set at 65,536 blob IDs, recursively partitions by hash prefix when necessary, and scans only matching CAS fan-out directories in each partition.
Source fingerprinting now caps directory entries, selected files, path bytes, and nesting depth, and refuses symlinks and lossy path names before the build script or automatic remote source setup can use the stamp.
RC-AA moves managed copies out of the legacy directory sweep without making two clients with different builds overwrite the same executable.
RC-E remains open because binary state operations still accept plain paths; production JSON reads and replacements now use typed owner constructors, and `StateFile<T>` locks read-modify-write operations, release high-water checks, first-use client-origin initialization, and remote audit-witness verification.
`StateFile<T>::try_update` now lets a validated decision abort while holding the lock, before any replacement is written.
Mutation testing exposed the second identity-key read after taking its lock as an untested error path; a scoped delayed read fault now requires an error and a successful retry after that failure.
The trust fault matrix also covers entropy, key persistence, and lock release failures, and the focused mutation task detected all 67 executed trust mutations in the local run.
Job phase writes now take a typed `StateFile<Phase>` lock and reject any transition outside queued, preparing, starting, running, and finished order.
Test fixtures have a separate test-only phase writer, and a boundary test checks both a skipped transition and a rewind after completion.
Windows now passes a protected owner-and-SYSTEM ACL to `CreateDirectoryW` when making each missing private directory, so this operation no longer spawns `icacls` or exposes a newly created directory before setting its ACL.
Existing Windows state paths now have their ACL inspected through the opened handle before they are trusted.
The current user and SYSTEM are the only accepted access grantees; the built-in Administrators group is also accepted as owner because existing Windows state can carry that owner while its DACL grants access only to the user and SYSTEM.
An unknown ACE type or more than 32 ACEs fails closed, and a reparse point cannot be accepted as a regular state file or directory.
One earlier Windows full-suite run failed three temporary state setups with missing-path or access-denied errors; those tests and then the full suite passed on rerun, so the cause of those particular missing paths remains unproven.
RC-F and RC-L remain open because source-specific argument types cover only some flows and peer wire values do not yet carry a general provenance label.
`Arg::path` and `Invocation::in_dir` now require a sealed `SafePath` implemented only for named local sources; ordinary `Path` values fail to compile at those sinks.
Local directory and detected-source-root fields are private, and the syntax gate confines their exceptional constructors and direct process working-directory calls.
The node now keeps authorization attached in `RoutedRequest<E>` while routing queries and commands, and admits jobs only from an `AuthorizedSubmission`; the syntax gate rejects plain-request handler signatures, a plain-submission admission signature, an unsealed command-authority trait, or a public proof field.
Configuration, cleaning, retry, and kill require their own private proof types, and the syntax gate checks their handler signatures and the exact command-action variants.
Inbound requests now enter as opaque `PeerRequest` values, which release the raw request only to `authz::authorize`; direct `Ingress` decoding of `Request` and `Submission` fails the syntax gate.
Editable configuration uses an `EditableToml` value returned by `ingress`, and Clippy rejects direct use of the underlying `DocumentMut` type outside that module.
Repository command words, runner names, and environment values now deserialize as `Labeled<String, Repository>` and become `Labeled<String, ApprovedRepository>` only with an `ApprovedProjectTargets` proof.
The declarative syntax gate rejects plain-string regressions in those fields and in the approved command-word type; peer wire fields remain to be migrated.
RC-K now has separate `LocalPolicy`, `RepositoryRequest`, and `ApprovedProjectJob` types.
Project job requests require an exact locally configured root and machine grant, `@all` expands only inside that grant, and approved machine values stay typed through submission.
The syntax gate requires those fields and prevents `run_named` from constructing a raw order; tests exercise absent and wrong roots, denied targets and overrides, and paths outside the source root.
